# Audit log dan prioritas terhadap codebase

## Audit command seluruh sesi

Semua 85 JSONL diproses per sesi: event command yang selesai diekstrak beserta perintah, kode exit dan outputnya tetap tersedia dalam log asli. Inventaris perintah per sesi tersimpan di `raw-local/multilang-20261103/agent-run-command-audit.txt`, disalin dan diverifikasi SHA-256. Pencocokan nama perintah adalah pemeriksaan otomatis, bukan sandbox atau pembuktian aliran setiap fakta.

- 34/34 sesi arm Riltra memiliki setidaknya satu command selesai dengan exit 0 yang memuat executable Riltra dan `scan`, `search`, `callers`, `callees` atau `semantic`. Ini membuktikan command berhasil, tidak membuktikan respons lengkap atau bahwa semua isi jawaban bersumber dari respons tersebut.
- Pada 34 baseline dan 17 reviewer tidak ditemukan command yang memuat nama executable Riltra. Setiap sesi memiliki command dengan pola pembacaan/pencarian teks; pencocokan pola tidak sendiri membuktikan isi yang berhasil terbaca.
- Command nonzero muncul di 30/34 baseline, 7/17 reviewer dan 26/34 arm Riltra; hitungan ini mencakup kegagalan yang kemudian diatasi, dan tidak berarti kegagalan sesi. Misalnya `rg` tidak tersedia pada sejumlah sesi. Semua sesi berakhir dengan exit 0 dan `turn.completed`.
- Reviewer `ts-same_name/review-1` mencoba membaca file skill di luar fixture; setidaknya sebagian instruksi skill ada dalam konteks/hasil perintah. Baseline `ts-reference/base-1` juga mencoba membaca skill. Pembatasan “hanya fixture” karena itu tidak ditegakkan. Pencarian nama `oracle`, `golden`, `docs/pilots`, database, `git log`, `git show` dan URL dalam command yang terekstrak tidak menemukan kecocokan; ini bukan bukti tidak ada akses lain, konteks awal lain, atau kebocoran terselubung.
- Hash fixture tetap sama setelah sesi, tetapi home arm dipakai ulang antara dua pengulangan dan workspace-write tersedia. Tidak ada bukti bahwa setiap fakta jawaban berasal dari satu alat tertentu; tidak ada isolasi buta yang bisa diklaim. Model aktual juga tidak muncul dalam metadata yang diperiksa.

Penilaian isi setiap jawaban dan perbedaan kepastian ada dalam [audit 85 sesi](audit-85-sesi.md). Jangan mengubah 31/34 dan 30/34 menjadi skor alat, karena source turut digunakan dan prompt berbeda.

## Prioritas berdasarkan hasil dan implementasi saat ini

1. **Reproduksi kandidat TypeScript yang hilang dengan producer nyata.** [Diagnosis](diagnosis-typescript.md) menemukan fakta definisi `display_name` kosong dan kandidat `owner-unproven` dalam DB, sementara perubahan satu nama pada salinan DB membuat kandidat terlihat. `crates/cli/src/index.rs` sudah mengambil `best[0].display_name` untuk semantic anchor dan memakai `called_name` untuk seleksi kandidat inbound; `crates/cli/src/edges.rs` sudah mempertahankan kandidat `owner-unproven`. Existing `crates/cli/tests/edges.rs` sudah menguji beberapa unresolved owner dan import scope, sehingga jangan membuat ulang kemampuan umum itu. Celah yang diamati adalah kombinasi **producer nyata, nama kosong, pemanggilan scope modul dan query callers**. Pertama tambahkan regresi yang mereproduksi kombinasi tersebut serta tabrakan nama; baru tentukan fallback aman tanpa mempromosikan kandidat menjadi `CALLS`. Counterfactual belum membuktikan solusi.
2. **Perluas validasi dengan provider dan source nyata, gunakan kemampuan yang sudah ada.** Corpus M6 sudah memiliki 82 tes existing yang lulus pada Windows dan WSL; jangan membangun ulang corpus sintetis. Tes Rust repository menemukan 16 lokasi oracle terbatas tetapi producer mencatat 197 error, duplicate dan output `UNKNOWN`/terpotong. Prioritasnya adalah menelusuri diagnostik producer dan memilih anchor yang bisa diaudit, lalu menambah repository TypeScript nyata dan kasus C++ clangd yang lebih dari satu fixture. C++ fixture sudah menemukan lokasi melalui LSP, tetapi `definitions` kosong dan hasil `Unverified`; perlu membandingkan kontrak provider sebelum menyebutnya cacat. Python dan provider C belum terbukti dalam run ini.
3. **Lengkapi parity dan freshness pada gap spesifik.** `crates/cli/tests/index.rs` sudah menguji stale dan rebuild, dan `crates/cli/tests/mcp.rs` sudah memuat tes syntax graph; suite index 44 dan MCP 61 sudah lulus pada Windows dan WSL. Pemeriksaan baru incremental JS/TSX baru mencakup satu edit dan satu search, bukan graph penuh. Tambahkan perbandingan CLI/MCP dan incremental/full untuk kasus yang menunjukkan gap nyata, termasuk stale dan paging, bukan mengulang suite yang sama sebagai fitur baru.
4. **Perbaiki protokol penilaian agent sebelum mengulangnya.** Bekukan unit penilaian dan oracle sebelum output; pisahkan penilaian lokasi, klasifikasi, identitas, uncertainty dan atribusi sumber. Isolasi reviewer secara teknis, pastikan model dapat diaudit, dan simpan home terpisah per pengulangan. Ini menangani kesalahan nomor baris dan perbedaan kepastian yang diamati tanpa menyimpulkan bahwa Riltra menyebabkan semua kesalahan agent.

Usulan di atas dipetakan ke hasil dan implementasi yang diperiksa, bukan klaim bahwa seluruh jalur atau seluruh pengujian repo telah ditinjau. Tidak ada perubahan kode produk pada audit ini.
