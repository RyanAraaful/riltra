# The clangd semantic provider pilot (M9)

The pilot that tested whether clangd can close the C++ semantic gaps
(E1, E7, E12) without touching Riltra's architecture.

**The report is `docs/m9-clangd-pilot.md`.** This directory is its evidence.

## What is here

| Path | What it is |
|---|---|
| `fixture/` | a small CMake C++17 project whose E1/E7/E12 cases carry their ground truth in the source: two `static_assert`s state what the compiler thinks of a construction and of a most-vexing-parse, and one file outside the build carries an ambiguity the compiler rejects with `C2668` |
| `method/` | the harness: the probe driver, the probe tables, the compilation-database builders, and the degradation experiments |
| `raw/` | the redacted output of every run (usernames and repository roots replaced; the system's own compiler path is kept, because it is part of the evidence) |

## How to reproduce

The pilot ran in an isolated bench root with a portable clangd and a
portable CMake, both extracted into that root, neither installed
system-wide, and neither on `PATH`. The MSVC Build Tools that are already
installed on the machine were used as the **ground truth** compiler.

```powershell
# 1. the tools (portable, into the bench root)
#    clangd:  https://github.com/llvm/llvm-project/releases  (clang+llvm-<v>-x86_64-pc-windows-msvc.tar.zst)
#    cmake:   https://github.com/Kitware/CMake/releases      (cmake-<v>-windows-x86_64.zip)

# 2. the fixture's compilation database, generated by CMake itself
cmake -S fixture -B <bench>\fixture\build -G "NMake Makefiles" -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build <bench>\fixture\build

# 3. MMSP's database, from the repository's own documented command
pwsh method/mmsp-cdb.ps1 -Clone <bench>\mmsp -Out <bench>\mmsp\compile_commands.json

# 3b. colmap's RECONSTRUCTED database (it is not the real build configuration)
pwsh method/colmap-cdb.ps1 -Clone <bench>\mmsp -Out <bench>\mmsp\colmap\compile_commands.json

# 4. the probes
pwsh method/probe.ps1 -Root <bench> -Probes method/probes.json -Out <bench>\raw\probes-shipped.json -Server <clangd.exe>
pwsh method/probe.ps1 -Root <bench> -Probes method/probes-colmap.json -Out <bench>\raw\probes-colmap.json -Server <clangd.exe>

# 5. the degradation experiments
pwsh method/robustness.ps1     -Root <bench> -Server <clangd.exe> -Out <bench>\raw\robustness.json
pwsh method/staleness.ps1      -Root <bench> -Server <clangd.exe> -Out <bench>\raw\staleness.json -Rounds 3
pwsh method/readiness.ps1      -Root <bench> -Server <clangd.exe> -Out <bench>\raw\readiness.json -Rounds 5
pwsh method/index-coverage.ps1 -Root <bench> -Server <clangd.exe> -Out <bench>\raw\index-coverage.json
pwsh method/coldstart.ps1      -Root <bench> -Server <clangd.exe> -Out <bench>\raw\coldstart.json

# 6. the environment evidence: tool versions, the databases, the compiler's
#    verdicts and what clangd itself reports (with and without a database).
#    It runs every command from the bench root, so no repository path
#    reaches the evidence.
pwsh method/collect.ps1 -Root <bench> -Tools <tools-root> -Out <bench>\raw\env
```

The CMake step needs the portable CMake on `PATH` (or its full path in the
command) for that one invocation; nothing else needs it.

The probe driver needs a registered repository: `riltra init --repo <path>
--name <name>` with `RILTRA_HOME` pointing at the bench home. The scripts
find the Visual Studio toolchain through `vswhere` (`method/msvc.ps1`), so
no Visual Studio path is hard-coded.

**A note on the compilation database.** clangd finds it by walking up from
the file, and it also looks in a `build/` subdirectory — that is how the
fixture's database is found, even though the fixture's sources are in
`src/`. The `mmsp\compile_commands.json` and
`mmsp\colmap\compile_commands.json` files are written by the two database
builders and are **not** the same thing: the first is the repository's own
documented build command, the second is a **reconstruction** and says so.

## Tooling used by the harness (not a Riltra dependency)

| Tool | Version | License | Origin | Role |
|---|---|---|---|---|
| clangd (LLVM) | 23.1.4 | Apache-2.0 WITH LLVM-exception | https://github.com/llvm/llvm-project/releases | the provider under test |
| CMake | 4.4.4 | BSD-3-Clause | https://github.com/Kitware/CMake/releases | generates the fixture's compilation database |
| MSVC Build Tools | 19.34.31948 (14.34.31933) | Microsoft Visual Studio license | pre-installed on the host | the ground-truth compiler |

None of them is a build or runtime dependency of `riltra`; they are host
tools the pilot downloads into its own bench root. The LLVM archive is
~264 MB compressed, CMake ~52 MB.
